# CI/CD 行为

## 变更影响与图构建

修改 `.dockerignore`、`pyproject.toml`、`.github/workflows/**`、`schemas/**` 或
`tools/images/**` 会影响全部变体。修改 `src/<family>/` 下的文件或命中该镜像族 `inputs` 的
文件，会影响该族全部变体。未包含在 inputs 中的纯文档变更不会构建镜像。

规划器先展开传递下游：基础镜像变更会重建全部消费目标；然后补齐构建选中产物所需的传递
上游。除非上游本身也受影响，否则它在计划中的 `publish` 为 `false`。最终顺序为拓扑序。

目标会按互不连接的图组件分组。CI 会构建和测试所有组件，记录失败后继续执行无关组件，避免
一个镜像图失败掩盖其他图的结果。

## 工作流矩阵

| 行为 | PR | 推送到 `main` | 手动发布 |
| --- | --- | --- | --- |
| 选择范围 | 变更闭包 | 变更闭包；首次推送为全部 | 全部、单一镜像族或单一变体 |
| 权限 | `contents: read` | `contents: read`、`packages: write` | 与 main 发布相同 |
| Registry 登录 | 否 | 本地测试通过后 | 本地测试通过后 |
| 镜像推送 | 从不 | 只推缺失的不可变标签 | 只推缺失的不可变标签 |
| 缓存 | 读取镜像族/变体 scope | 读取并写入镜像族/变体 scope | 读取并写入镜像族/变体 scope |
| 浮动标签 | 从不 | 不可变标签成功后提升 | 与 main 发布相同 |

因此 Fork PR 保持只读且不会获得包凭据。空计划会跳过 Buildx 和全部镜像操作，但仓库校验仍会
执行。

## 发布事务

main 工作流依次执行仓库校验、本地构建与冒烟测试、使用 `GITHUB_TOKEN` 登录、未推送的预检
构建，以及本地 digest 与 GHCR 的比较。不可变标签缺失时保留在发布计划中；digest 一致时作为
幂等重试移除；digest 不同则失败。全部缺失的不可变标签推送完成后才提升浮动标签。

并发组 `publish-images-main` 串行化发布任务，且不会取消正在执行的发布。缓存 scope 为
`<family>-<variant>`，避免无关变体互相覆盖。所有第三方 Action 固定到 commit SHA。

生成的 plan、metadata 和 Bake 文件只属于当前工作流，不包含秘密。
