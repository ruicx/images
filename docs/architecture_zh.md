# 架构

## 仓库模型

每个镜像族都是 `src/` 下的一个目录，包含 `image.yml`、一个参数化 Dockerfile、双语文档和
冒烟测试。清单是唯一事实来源，工作流中不手写镜像矩阵。

这种分层让发行意图保持声明式：清单描述变体和依赖边，Dockerfile 描述构建顺序，共享脚本
提供能力级安装，Python 工具把这些输入转换为一个经过校验的执行图。完整契约见
[清单参考](manifest-reference_zh.md)。

`images plan` 根据各清单的 `inputs` 把变更映射到镜像族，展开传递下游，并补齐构建所需的
上游。生成的 Bake 图把内部依赖映射为 `target:<name>` 构建上下文，因此 PR 验证使用同一提交
刚构建的基础镜像，而不是 GHCR 中的旧版本。

互不连接的依赖图会形成独立的 Bake 组件组。CI 会尝试全部组件后再汇总结果，因此一个镜像族
失败不会掩盖无关镜像族的有效结果。准确的变更影响规则见 [CI/CD 行为](ci-cd_zh.md)。

## 镜像组合与缓存边界

共享脚本负责能力行为及参数校验；Dockerfile 只负责选择能力、传递参数和声明执行顺序。构建
参数通过具名脚本选项传入，因此用户选择、工作目录所有权和软件源选择等值分支应由对应脚本
处理，而不是在多个 Dockerfile 中重复 shell 判断。

可以独立变化的能力采用相邻的 `COPY` 和 `RUN`。如果一次 `COPY` 多个脚本，即使之后拆成多个
`RUN`，修改其中任一脚本仍会让后续所有能力的缓存失效。满足依赖顺序后，稳定或昂贵的能力放
在前面，便宜或经常变化的能力放在后面。这里有意用少量 OCI 层换取有效的 BuildKit 缓存边界、
清晰的构建日志和可定位到单一能力的失败；这并不意味着拆分每条 shell 命令，软件安装和 apt
lists 清理仍必须位于同一个 `RUN`。

用户、SSH 和工作目录是彼此独立的能力。用户配置首先复用已有 root 账号，或按
`DEFAULT_USER` 创建同名非 root 账号；SSH 策略随后绑定到解析后的账号；工作目录能力最后创建
`WORKSPACE_DIR` 并设置其所有权。工作目录可配置，但必须是绝对路径，不能是 `/`，也不能包含
`.`/`..` 路径段。工作目录布局不放进用户管理能力，使两者可以独立复用而不引入镜像专用策略。

容器命令与 login shell 有意保持独立。镜像可以继续使用 Bash 作为默认命令，同时由开发 shell
能力把账号的 login shell 改为 zsh，供 SSH 会话使用。`docker exec` 调用者显式选择所需命令，
不使用包装脚本根据调用环境猜测 shell。

构建期软件安装使用基础镜像的上游源。清单的 `mirror` 会转换为 `PACKAGE_MIRROR`，最终镜像源
能力在所有构建期安装结束后，统一负责校验并选择最终保留的软件源：`upstream` 不做修改，
`aliyun` 重写 apt 和 pip 配置。这个取舍既改善 GitHub 托管 runner 的构建性能，又允许生成面向
中国网络环境的运行时镜像，并避免不确定的运行时网络探测。最终环境可以保留
`PACKAGE_MIRROR` 供检查，但容器启动过程不会根据它执行任何操作。

## 标签生命周期

不可变标签为 `<variant>-<short-sha>`。发布前，CI 计算本地产物 digest 并检查 GHCR：标签不
存在则推送，digest 相同则跳过，冲突则终止发布。所有不可变标签就绪后，CI 才更新浮动的
`<variant>` 标签。

要求可复现的使用者必须固定不可变标签或 digest。浮动变体标签仅为便利通道，每次成功合并后
都可能变化。

## 信任边界

PR 只有仓库只读权限，不登录 GHCR，也不推送镜像或缓存。主分支发布任务仅获得
`contents: read` 和 `packages: write`。构建秘密只能通过 BuildKit secret mount 使用，禁止经由
`ARG`、`ENV` 或 `COPY` 传递。

SSH 是显式运行策略，支持 `disabled`、`key-only` 和 `password`。`key-only` 在未挂载
authorized keys 时拒绝启动。`login_user` 会解析为镜像的 `DEFAULT_USER` 或 root，且
`AllowUsers` 将 SSH 限制到该账号。密码模式可通过运行时挂载的 `SSH_PASSWORD_FILE` 为解析后
的账号设置密码；密码禁止写入镜像层、清单、构建参数或环境变量。未提供运行时密码文件时，
账号保持锁定。
