# 兼容性与生命周期

清单 schema 版本、CLI 命令名、计划 schema、镜像名、变体标识和标签格式都是公共兼容接口。
schema version `1` 可以增加兼容的可选字段；删除字段或改变字段含义必须使用新版本，并提供有
文档说明的迁移周期。

修改镜像族名称会改变 GHCR 包名，修改变体标识会创建新的标签通道。两者都应视为“删除并新增”：
在镜像族的中英文 README 中公布替代项；条件允许时保留旧标识一段弃用期；禁止把旧通道指向
语义无关的软件。

删除变体只会停止后续构建，自动化不会删除既有不可变标签。浮动标签是可变的便利通道；构建批次
不可变标签和 digest 才是回滚机制。消费者回滚时应固定到之前的不可变标签或 digest。把浮动
标签回退属于自动工作流之外的维护者显式操作，必须留下记录。

新的 CI 发布使用 `<variant>-<short-sha>-<run-id>-<attempt>`，替代原有的
`<variant>-<short-sha>` 格式。已有不可变标签保持不变。本地 CLI 不传 `--build-id` 时保留
旧格式；CI 始终传入构建批次，以支持滚动重建。

未被任何清单 `inputs` 引用的共享脚本属于待迁移能力。它们会被保留，但不属于首期受支持的
构建范围。只有当清单消费该脚本、脚本符合当前参数与安全规则，并且对应结果有冒烟测试覆盖时，
该脚本才成为受支持能力。

每个镜像族支持一个原生平台：`linux/amd64` 或 `linux/arm64`。仓库不承诺 SBOM、provenance
或漏洞门禁产物。增加这些能力时必须
保持清单和标签契约，或者提供明确的版本化迁移。
